# Data Validation & Event Review

WatchOut! 프로젝트의 데이터 무결성 검증과 XML 기반 이벤트 후보 구간 수동 검토를 지원하는 모듈입니다.

## 1. 목적

데이터셋 구축 과정에서 영상·라벨 매칭 오류, 파일 누락, 중복 데이터, 이벤트 시간 구간 오류 등을 확인하고, 이벤트 후보를 사람이 검토할 수 있도록 지원합니다.

## 2. 주요 스크립트

### `validate_dataset_300.py`

**이상행동 데이터셋 검증**

- 이상행동 유형별 영상 개수 확인
- MP4 및 XML 파일 존재 여부 확인
- 영상과 라벨의 매칭 상태 검사
- 중복 영상 여부 확인

### `create_review_list_300.py`

**수동 검토 대상 생성**

- XML 이벤트 후보 구간 분석 결과 활용
- 추가 검토가 필요한 이벤트 구간 추출
- 이벤트별 검토 상태를 기록할 CSV 생성

**주요 결과**
- 수동 검토 대상 영상: 63개
- 수동 검토 대상 후보 구간: 126개

**주요 출력**
- `processed/segments_review_300.csv`

### `create_event_previews_300.py`

**이벤트 구간 미리보기 생성**

수동 검토자가 이벤트의 시작·종료 구간을 확인할 수 있도록 5개 시점의 이미지를 생성합니다.

| 시점 | 설명 |
|---|---|
| Before | 이벤트 시작 이전 |
| Start | 이벤트 시작 시점 |
| Middle | 이벤트 중간 |
| End | 이벤트 종료 시점 |
| After | 이벤트 종료 이후 |

**주요 출력**
- `processed/event_previews/`

### `review_events_300.py`

**이벤트 구간 수동 검토**

이벤트 미리보기와 이벤트 시간 정보를 바탕으로 구간의 적절성을 검토하는 스크립트입니다.

검토 선택 항목:

| 선택 | 의미 |
|---|---|
| `1` | 적절한 구간 |
| `2` | 시작·종료 시간 수정 필요 |
| `3` | 이벤트 판단 어려움 |
| `s` | 건너뛰기 |
| `q` | 저장 후 종료 |

검토 상태는 CSV 파일에 기록합니다.

정지 이미지로 판단하기 어려운 사건은 원본 영상을 추가 확인해야 합니다.

### `reset_review_status.py`

**수동 검토 상태 초기화**

- 기존 검토 결과 백업
- 수동 검토 상태를 `pending`으로 초기화
- 검토 작업을 처음부터 다시 진행할 때 사용

이미 완료된 검토 상태를 변경하므로 실행 시 주의가 필요합니다.

### `final_dataset_check_300.py`

**이상행동 데이터 최종 검증**

- 이상행동 영상 300개 확인
- VLM 입력 프레임 참조 확인
- 이벤트 후보 구간 및 수동 검토 대상 확인
- 메타데이터 오류 검사
- 검증 결과 JSON 생성

**주요 출력**
- `processed/final_dataset_report_300.json`

### `validate_combined_400.py`

**최종 통합 데이터셋 검증**

이상행동 300개와 정상 구매행동 100개를 통합한 VLM 입력 데이터를 검사합니다.

주요 검사 항목:
- 전체 400개 영상 수 확인
- 그룹별 데이터 개수 확인
- 영상 및 프레임 ID 중복 검사
- 프레임 파일 경로 존재 여부 확인
- 이벤트 후보 구간 시간 정보 확인
- 수동 검토 상태 집계

**주요 출력**
- `combined/final_validation_report_400.json`

## 3. 주요 검증 결과

| 항목 | 결과 |
|---|---:|
| 전체 영상 | 400 |
| 이상행동 영상 | 300 |
| 정상 구매행동 영상 | 100 |
| VLM 프레임 참조 | 6,400 |
| 이상행동 이벤트 후보 | 363 |
| 수동 검토 대상 구간 | 126 |

위 수치는 최종 데이터셋 구성 및 패키징 결과입니다.

## 4. 검증과 정답 확정의 차이

데이터 무결성 검증을 통과했다는 것은 파일 구조, 경로, ID 및 메타데이터가 일관된다는 의미입니다.

**이벤트가 실제로 발생했는지, 구간 경계가 정확한지, 정상 구매행동에 이상행동이 없는지는 별도의 검토가 필요합니다.**

따라서 데이터 구조 검증 결과를 모델 성능이나 정답 라벨의 정확도로 해석하지 않습니다.

## 5. 향후 작업

- 미검토 이벤트 구간 수동 확인
- 이벤트 유형과 구간 경계 보정
- 정상 구매행동 데이터 표본 검토
- 평가용 정답 라벨 확정
- 모델 추론 결과와 정답 비교
